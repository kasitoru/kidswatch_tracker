Integration for tracking Kids Watch devices (such as HONOR Choice Kids Watch) in Home Assistant.

## Installation

### Method 1: Via HACS (Recommended)

1. Ensure you have [HACS](https://hacs.xyz) installed
2. In HACS, go to "Integrations"
3. Click the three dots in the top right → "Custom repositories"
4. Add the repository URL: `https://github.com/kasitoru/kidswatch_tracker`
5. Select category "Integration"
6. Search for "Kids Watch Tracker" in HACS and install it
7. Restart Home Assistant

### Method 2: Manual Installation

1. Download the [archive](https://github.com/kasitoru/kidswatch_tracker/archive/refs/heads/main.zip) with the latest version of the integration
2. Copy the `custom_components` folder to your `homeassistant` directory
3. Restart Home Assistant

## Configuration

### UI Configuration

1. After installation, go to Settings → Devices & Services → Integrations
2. Click "Add Integration"
3. Search for "Kids Watch Tracker"
4. Fill in the configuration form:
   - **Country Code**: Select your country from the dropdown list
   - **Phone Number**: Phone number associated with your Kids Watch account
   - **Password**: Password for your Kids Watch account
   - **Update Interval**: How often to update location (seconds, default: 60)
   - **Force Update Location**: If enabled, will request location update on every poll

### Configuration Options

After setup, you can adjust settings via the integration's "Configure" menu:

- **Update Interval**: 30 to 3600 seconds
- **Force Update Location**: Enable/disable

## Entities

For each child/device a single HA device is created with the following entities:

| Entity | Domain | Category | Description |
|--------|--------|----------|-------------|
| Location | `device_tracker` | — | GPS coordinates of the watch |
| Battery | `sensor` | Diagnostic | Battery level, % |
| Last location update | `sensor` | Diagnostic | Timestamp of the last location reported to the cloud (`device_class: timestamp`, displayed in your local time zone) |
| Charging | `binary_sensor` | Diagnostic | Whether the watch is charging |

The device tracker has **no extra attributes** — all additional data is exposed as
separate entities.

### Entity IDs

Entity IDs are generated by Home Assistant from the child's nickname at first setup.
For example, nickname `Alisa` produces:

- `device_tracker.alisa`
- `sensor.alisa_battery`
- `sensor.alisa_last_location_update`
- `binary_sensor.alisa_charging`

Use Latin nicknames in the Kids Watch app for predictable entity IDs, or rename them
afterwards in Settings → Devices & Services → Entities. Renaming an entity ID does not
break the integration.

### Availability

- If the cloud has no location for a watch yet (e.g. it has never reported one), setup
  still succeeds and the entities are created as **unavailable**. They become available
  automatically as soon as the first data arrives.
- An entity is also unavailable while its own value is unknown (e.g. no battery value
  in the last report).
- On temporary API errors the integration keeps the last known data for up to
  **10 consecutive failed polls**, then marks the device unavailable until the next
  successful update.

> **Note:** In version 2.0.0 the `battery_level`, `locate_time` and `charging` attributes
> of the device tracker were removed. Use the **Battery**, **Last location update** and
> **Charging** entities instead.
